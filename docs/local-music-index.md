# 本地音乐索引与增量扫描

目录能力由 `musaic_query` 提供；SQLite 数据库由应用的
`lib/storage/music/music_index.dart` 管理，扫描协调位于
`lib/services/music/directory_music_library.dart`。使用 sqflite，测试使用
sqflite_common_ffi。引入前应用没有持久数据库，因此没有另一套存储需要迁移。
当前 schema 为 v1；首次建立独立 music_index.sqlite，不修改现有用户文件。
后续升级必须增加版本并写增量迁移，禁止删库重建或降级清库。

## 启动与展示

应用装配在 lib/app/app.dart 中打开数据库并读取缓存，在任何原生目录授权
检查或遍历前发布已存音乐列表。上次选择了文件夹来源时，自动展示该来源，
然后启动异步增量扫描。这份持久化索引只保存添加的目录资源，不复制系统媒体库；系统媒体库和示例来源保持现有行为。

现有来源面板增加音乐文件夹入口、添加目录、取消、强制读取标签、重新授权
及移除来源。目录内容进入现有专辑界面，封面只在可见项请求时提取。
此功能是索引与浏览能力；目录歌曲未接入播放接口，隐藏其播放按钮，不新增播放器，也不会
把无播放授权的目录资源冒充可播放资源。现有系统媒体库播放不变。

## 数据与身份

sources 保存来源身份、名称、私有授权引用及扫描状态；files 以资源 ID 为
主键保存轻量枚举信息、元数据 JSON、文件夹关联和验证时间；memberships
保存来源与资源的关联、扫描批次。批次号在数据库中递增，避免重启和时钟变化造成复用。同一资源可属于多个来源但只显示一次；优先使用扫描成功的授权来源，某个重叠授权失效不会遮蔽另一有效来源。
封面只保存源资源引用，不存图片字节。展示标题缺失时使用文件名，不回写为
原始标签。同名、同大小或相同标签不能证明两个文件相同。

Android SAF 身份由 provider authority 和 document ID 组成；普通文件与
目前 iOS 文件使用标准化 URL，改名/移动按删除与新增处理。系统媒体库仍走
系统索引，不转换成物理目录扫描。不同来源类型不凭标签擅自去重。

## 增量与删除安全

每次刷新仍需轻量枚举以发现变化。可靠文件大小/修改时间未变时复用标签；
新增、变化、上次解析失败或强制刷新才解析。第三方提供者的修改时间不默认
可信：最多每天重新验证一次；缺失时间戳也按此策略处理，手动强制刷新可
提前验证，并清理封面磁盘缓存以处理保留了大小和时间戳的内容变化。标签读取前后原生检查文件状态，读取过程中变化则保留错误待重试。
这一策略不是内容哈希，大小与修改时间被人为保持不变的文件需强制刷新。

最多一次刷新，重复请求共享当前 Future，下一次显式请求可强制刷新。
每页至多 128 项，批量写入数据库；取消在原生读取返回后、下一次读取和
提交前检查。已经提交的批次保留，取消不进行删除。标签单文件失败保留
旧标签并标记失败，其他文件继续处理。列表在一次刷新结束后批量发布，
进度按页更新，避免逐首重建目录界面。

只有整个来源完整枚举成功才清理该来源未见关联；任何目录失败、权限失效、
云提供者仍在加载、取消或进程中断都不能被解释为删除。无其他来源关联的
资源才从索引移除。中断批次在下一次数据库打开时标记 interrupted，重新扫描
安全恢复。目录封面单独记录，音频不变也能发现封面新增、修改及删除。

移除来源只删应用记录并释放授权，不删用户源文件。授权失败保留缓存，用户
可以重授同一目录；选择其他目录不能静默替换原来源。恢复失败可能意味着
来源已移动，需新增新来源后手动移除旧来源。

## 后台处理与写入成本

Android/iOS 的目录 I/O、标签与封面处理继续使用原生后台队列。应用在一个
SQLite 事务中读取来源、文件和关联三组数据，不随来源数量逐个重复查询。
`directory_catalog.dart` 在一个 `compute` worker 中完成 JSON 解码、健康来源
选择、目录统计、专辑分组和按资源 ID 建立查找表；每个文件只解码一次，重叠
来源复用解码结果。主 isolate 按批次发布 signals，封面组件按 ID 直接找歌曲，
不再遍历整个音乐列表。缓存读取、扫描、添加、重新授权和移除来源串行执行，销毁时等待正在进行的
操作，跳过尚未开始的工作，避免重新添加的授权被旧移除操作释放或读取已关闭的数据库。

每页仍至多 128 项。未变化文件只更新 memberships 的已见批次，不重写 files
中的标签和定位信息；轻量信息变化（例如稳定 ID 的文件改名）会更新文件行，
但不会因此重新读取标签。扫描结束一次性发布同一快照的歌曲、专辑和目录统计。
当前数据库 schema 不变，不需要迁移或清理用户数据。

后台 worker 指应用进程内的计算隔离，不是系统常驻任务。Flutter Web 的
`compute` 不会创建 isolate；应用原生目录入口只用于 Android/iOS，不能把这些
测试结果表述为 Web 后台线程性能。

## 后续竞态复查

来源操作与扫描共享串行队列，重复刷新仍共享同一 Future；排队中的刷新也能取消，
失败操作不会阻断后续队列。重复销毁共享完成信号，数据库在正在执行的来源操作
结束后关闭。新扫描重置计数，避免第一批返回前展示上次的统计。

封面内存缓存只有新增键才淘汰旧项；失效请求只能移除它自己，不能移除后续同键
请求。缓存键包含授权来源，重新授权后不会复用旧授权的请求。封面候选读取遇到
刷新或销毁时，不会将旧查询结果重新填回已清理的缓存。

本轮补充 8 项回归测试，相关测试合计 47 项通过，改动文件 analyze 无问题。
对照修复前实现，来源添加/销毁、旧封面请求失败、满容量命中及不同授权来源
这 5 项测试失败，修复后通过；未将测试替身当作真机授权验证。

本轮 Android debug APK 构建通过，iOS 模拟器构建、启动与热重启通过。随后按用户要求修复了既有检查问题，并重跑全量检查，结果见上文。

## 插件与索引完整复查

部分失败页面可以同时包含正常条目和错误。应用提交正常条目，但保留未见记录，
并把来源和摘要标记为未完成；文件提供者的错误空游标不能触发删除。目录统计
查询也加入服务队列，销毁等待已请求的统计结束，避免事务执行中关闭数据库。

原生封面缓存现在使用实时轻量指纹，并在写入前复核；缺失封面、未知时间戳和
强制清理不会继续命中旧图。未知指纹与清理后的输出路径也会变化，以同时更新
Flutter 解码缓存。切换歌曲时按资源身份隔离封面组件；插件仅在显式设置
keepOldArtwork 时保留上一请求的图片。详见插件 DIRECTORIES.md。

插件 Dart/widget/interface/Web 测试共 19 项通过，Android JVM 测试 17 项通过。
